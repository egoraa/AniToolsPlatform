## Ключевые решения (кратко; полная версия — в спеке)

- Три сущности: `group` (структура: владение модулями/подгруппами, экспорт портов
  как алиасы, connect по путям) + `pipeline` (корневая группа + service_directory +
  module_context) + `pipeline_runner` (пул потоков, жизненный цикл).
- Потоки: пул из N `std::jthread`; `assign(group&, index)`; несколько групп на
  поток — норма, цикл потока по кругу; группа без назначения — inline в цикле
  ближайшего назначенного предка (в позиции своего порядка вставки); корень без
  назначения → поток 0; пустая конфигурация = однопоточный пайплайн.
- Проверка `safe`-входов: критерий — граница потоков (не групп), выполняется
  раннером на шаге 1 `start()` до каскадов; записи соединений в группе хранят
  группы-владельцы сторон.
- Ошибки: initialize/start — fail-fast с откатом в обратном порядке; iterate —
  первый exception_ptr побеждает, request_stop всему пайплайну, `wait()`
  перебрасывает, `error()` возвращает.
- Раскладка: новые классы в `src/atp/` (header-only, цель `atp_host` INTERFACE
  поверх `atp_platform`); `module_loader.hpp` переезжает из `include/` в `src/`;
  в `include/` — SDK автора модулей + один аксессор `io_base::thread_safe()`.
- `group::make<M>()` реализует отложенный «вариант A» владеющего реестра
  (память `module-registry-variant-a`).
