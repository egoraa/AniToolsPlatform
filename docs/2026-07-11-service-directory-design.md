# Справочник сервисов и контекст модуля — дизайн

Дата: 2026-07-11. Статус: одобрен (вариант A из брейншторма).

## Задача

Модуль при инициализации должен получать интерфейс, через который он регистрирует
себя, чтобы другие модули могли найти его на старте и звать его **типизированный
API** — без `dynamic_cast` и с учётом DLL-границ.

## Решение (вариант A — публикация типизированных сервисов)

### `service_directory` (`include/atp/service_directory.hpp`)

Невладеющий справочник «кто что предоставляет». Ключ — пара
(имя поставщика, тип интерфейса):

- `provide<TService>(std::string name, TService& service)` — публикация;
  пустое имя — `invalid_argument`, дубликат (имя, тип) — `runtime_error`.
  `TService` указывается явно — вывод из аргумента дал бы конкретный класс
  модуля вместо интерфейса. const-типы отвергаются requires-клаузой.
- `at<TService>(name)` / `find<TService>(name)` — пара в духе std::map
  (at бросает, find возвращает nullptr); at различает «имени нет» и
  «имя есть, интерфейса нет» — зеркально module_registry.
- `remove(name)` — все публикации имени; `remove<TService>(name)` — одна.

Внутри: `unordered_map<string, map<type_index, void*>>` с инвариантом
«внутренняя map не пуста» (как registry_ в module_registry).

Типобезопасность без dynamic_cast: `void*` достаётся только под тем же
статическим типом, под которым положили (совпадение по `type_index`), поэтому
обратный `static_cast` корректен по построению — та же дисциплина, что у
`input_base::accepts()/deliver()`.

НЕ потокобезопасен (фаза настройки). Времена жизни — контракт на вызывающем,
как у io-соединений: снять записи до разрушения сервиса.

### `module_context` (`include/atp/module_context.hpp`)

Агрегат ссылок на службы платформы, передаваемый модулю:

```cpp
struct module_context {
    service_directory& services;
};
```

Новые службы добавляются полями без ломки сигнатур жизненного цикла
(но раскладка контекста — часть ABI плагинов).

### Жизненный цикл (`module_base`)

`initialize(module_context&)`, `start(module_context&)`, `stop(module_context&)`;
`iterate` — без контекста (горячий путь). Протокол: publish в initialize,
lookup в start — двухфазность делает порядок инициализации модулей неважным;
симметричное снятие публикаций — в stop.

### ABI

Смена виртуальных сигнатур `module_base` несовместима — `plugin_abi` растёт до 2.

## Отвергнутые варианты

- B: справочник `module_base&` + `static_cast` к конкретному классу модуля —
  непроверяемый каст, потребитель тянет полный заголовок модуля, хрупко через DLL.
- C: «API соседа» как IO-порты (queued_input команд) — не прямой типизированный
  вызов, очередь там, где нужен синхронный вызов.
