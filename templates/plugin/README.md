# Шаблон плагина

Минимальный проект плагина, который собирается **против установленного SDK** и о дереве исходников
платформы не знает ничего. Скопируйте каталог куда угодно — путей наружу здесь нет.

```bash
# 1. поставить SDK куда-нибудь
cmake -S <платформа> -B build
cmake --install build --prefix /куда/нибудь/atp-sdk

# 2. собрать плагин отдельным проектом
cmake -S templates/plugin -B build-plugin -DCMAKE_PREFIX_PATH=/куда/нибудь/atp-sdk
cmake --build build-plugin
```

`CMakeLists.txt` состоит из трёх содержательных строк: `find_package(AniToolsPlatform)`,
`atp_require_plugin_abi(8)` и `atp_add_plugin()`. Вторая — не формальность: когда платформа
поднимает `plugin_abi`, конфигурация здесь обязана упасть, пока плагин не пересмотрели. Остальное
(скрытая видимость, имя файла, тип цели, связывание только с `atp::platform`) ставит `atp_add_plugin`
— руками эти свойства не выписывают.

## Что здесь проверяется, кроме сборки

`pipeline.json` соединяет модуль этого плагина с модулями `atp_demo_plugin`: `counter` → `doubler` →
`printer`. Оба конца каждого соединения приходят из **разных библиотек**, собранных разными
проектами, — единственное место в репозитории, где это так. Вход берёт `int`, про который все
библиотеки согласны заведомо; выход отдаёт `std::string`, и вот он проверяет настоящее: опознание
типа по имени через границу и освобождение буфера той стороной, которая его не выделяла.

Запуск (плагин и конфиг кладутся рядом с `atp_app`):

```bash
atp_app pipeline.json      # печатает строки "template-plugin: N -> M"
```

Ровно это делает CI-джоб `out-of-tree plugin`.
